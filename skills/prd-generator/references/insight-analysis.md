# 洞察分析（六维度）

在澄清完需求、选模板之前，先做一轮洞察分析。目标：**跳出需求本身**，从更高维度看这个需求的本质价值、机会与风险。
产出直接写进 `prd` 对象的 `insights` 字段（Markdown），最终进入 `prd.md` 第 9 章。

## 输入

- 用户的原始需求描述；
- 第 1 步澄清得到的问答；
- 可选：用 `web_search` 搜到的行业/竞品信息（只当素材，注明来源，不编造）。

## 方法：第一性原理

1. **拆解** — 把问题拆到最本质的组成部分；
2. **质疑** — 挑战默认假设和行业惯例；
3. **重建** — 基于已知事实重新构建假设；
4. **验证** — 检查逻辑是否自洽，是否有反例。

核心问题（每个维度都要回答其中一部分）：

- 这个需求解决的是真问题还是伪需求？
- 用户说的是什么，但真正想要的是什么？
- 行业默认做法一定对吗？有没有例外？
- 如果失败了，最可能的原因是什么？

## 输出格式（每个维度都按这个结构写）

```markdown
### 维度X：标题

**🔍 依据**
（支撑这个判断的事实、数据或逻辑链；对话里的信息、搜索结果都算。没有数据就讲逻辑。）

**💡 判断**
（基于依据的洞察结论，要具体、有立场，不能是废话。）

**🎯 建议**
（基于判断的具体行动建议，要可执行，能落到 PRD 的某个字段或功能上。）
```

## 六大维度

### 维度一：行业洞察

**核心问题**：这个需求所处赛道的现状如何？天花板在哪里？趋势往哪走？

思考角度：
- 增量市场还是存量市场？市场集中度如何？
- 监管/政策对赛道的影响？
- 技术变革正在改变什么？
- 这个需求是顺势而为还是逆势而上？天花板低值不值得做？

### 维度二：用户痛点深挖

**核心问题**：表层需求背后，用户的真实动机和心理模型是什么？

思考角度：
- 用户说的「功能需求」背后的「情感需求」是什么？
- 用户当前的 workaround（临时方案）暴露了什么痛点？
- 是「必须」还是「想要」？是高频刚需还是低频可选？
- 用户愿意为这个痛点付出多少成本（时间/金钱/学习成本）？
- 没有这个功能，用户会怎么解决？

### 维度三：竞品盲区

**核心问题**：现有竞品忽视了什么？有没有体验断点或被低估的机会？

思考角度：
- 竞品都做了什么？它们**共同**忽略了什么？
- 有没有「显而易见但没人做」的机会？
- 差异化应该在功能、体验，还是心智？
- 竞品为什么没做？是没想到还是做不了？我们做了竞品多久能抄？

### 维度四：反直觉判断

**核心问题**：有哪些与常规认知相反的发现或建议？

思考角度：
- 行业共识是什么？这个共识可能错在哪里？
- 哪些「常识」其实是偏见或惯性思维？
- 有没有看似正确但可能有害的做法？
- 这个需求最大的悖论是什么？有没有「不做什么」比「做什么」更重要的时刻？

### 维度五：关键风险预判

**核心问题**：最可能翻车的环节在哪里？怎么应对？

思考角度：
- 技术风险：实现复杂度、集成难度、性能瓶颈；
- 业务风险：用户接受度、改变用户习惯的难度；
- 市场风险：时机、竞争加剧；
- 组织风险：团队能力、资源；
- 优先级风险：与其他需求的冲突。
- 反问：如果这个项目失败了，最可能的一个原因是什么？

### 维度六：增长杠杆

**核心问题**：哪个环节的设计能带来非线性增长？

思考角度：
- 哪个功能点能带来网络效应或规模效应？
- 有没有「一分投入，十分回报」的杠杆点？
- 增长飞轮在哪里？用了 A 会不会自然用到 B？
- 数据和算法能否形成壁垒？有没有「越用越好用」的正向循环？
- 如果只能做一个功能让用户爱上产品，是哪个？

## 输出要求

1. **六个维度全部覆盖**，每个维度至少 2–4 句实质内容；某一维度确实无信息可写时，明确写「信息缺口」+ 初步判断，不要凑字数。
2. **每个判断都要有支撑逻辑**，允许有争议性观点，但必须给推理过程。
3. **每个建议都要可执行**，不能是「做好用户体验」这种废话。
4. 洞察要能反过来影响 PRD：某个判断如果改变了优先级、范围或验收标准，明确说出来（例如「因此建议把 X 降为 P1」）。
5. 信息不足时：明确指出缺什么信息、基于现有信息的初步判断、建议补充的调研方向。

## 语气

像一位资深产品经理在做内部分享：

- 直接、坦诚、不绕弯子；有观点、有立场、不和稀泥；
- 有数据讲数据，没数据讲逻辑；
- 承认不确定性，但不因此放弃判断。

避免：教科书式罗列、「一方面另一方面」式和稀泥、「用户体验很重要」类废话、没有支撑的猜测。

## 输出示例（仅参考结构）

```markdown
### 维度一：行业洞察

**🔍 依据**
- 语言学习 App 的留存主要靠「习惯回路」，打卡是低成本高感知的抓手；
- 头部产品都已内置打卡，但多数只做「连续天数」，缺少即时反馈闭环；
- 生成式 AI 让发音评分成本显著下降，这是近两年的结构性变化。

**💡 判断**
打卡本身不构成差异化，真正的机会在「打卡 + 即时反馈」的闭环；只做统计不做反馈，用户三周内必然流失。

**🎯 建议**
把「跟读打分」与「打卡」绑成同一动作（完成跟读即打卡），MVP 只保留这一个闭环，其余（排行榜、勋章）全部放 P1。
```
